# 分工实现与独立审核

先读 [启动策略](../../../docs/review-policy.md)。这是分工验收工作流，不因普通问答自动委派。
历史调用名 sol-terra-gemini 指向本技能。默认 Gemini 关闭；只有明确启用时读可选适配器。

## 角色与上下文

- 执行者：GPT-6 Sol / low，按合同连续实现、自检和修复，只有它写目标生产文件。
- 统筹审核者：GPT-6.1 Sol / high，负责中性任务合同、启动决定、证据要求和争议处理。
- 首次/全新审核：使用统筹审核角色的全新上下文、fork_turns=none，不继承调度历史、实现者解释或旧结论；审核者未实现或共同设计当前版本。
- 统筹态与盲审态是同一角色的不同上下文，不把“看过实施过程的统筹”冒充盲审者。当前运行模型/权限不由配置证明；运行不支持时如实报告，不静默代审。
- 执行者也用隔离上下文，仅给中性合同、必要原始材料和允许修改范围，不复制统筹私有评估或预期评分。普通修复复用执行者自身上下文。

## 闭环

1. 保存原始要求、原子合同、保留条件与证据计划。目标项目规则优先，不缩小授权范围。
2. 派执行者完成一组有明确验收目标的实现与自检；不按文件/每一步拆分调度。只有独立模块才并行增加执行worker。
3. 保存原始差异和检查证据，填写启动评估，运行 bin/workflow.mjs decide。未知不当false；免审须有事先策略，不可验收失败后改判。
4. prepare先修复/补证据；self_check_only明确未独立审核；stop报告剩余项。需要审核时冻结完整相关源码、合同、证据和分阶段阅读索引。
5. 首次审核/全新终审创建 independent_reviewer，新上下文只给中性资料及路径；先固定首次发现再读历史结论。普通返工由原审核者增量复验。
6. 审核者返回有证据的问题、目标和复验方法，不写实施补丁。只将必要问题事实/目标/保留条件发给执行者，不传审核私有推理或期望分数。
7. 执行者修复后重新冻结，记录新启动决定；默认三轮上限。分别报告本轮、技术、全局与独立性，不把命令成功当通过。

## 不可省略的边界

审核者拥有自己的取证登记、检查点和问题账本；实现者不能代标已读或改写审核报告。
上下文丢失或换人，换context-id并重取必要原始材料；连续复验才可按实际哈希复用。
污染、共同设计、严重漏检、实质争议或重要交付按策略触发全新终审。
用户要求/规则、技术事实、任务相关可用性和偏好分开；偏好与低置信度推测不阻断。
同系列模型仍有共同偏差；不同模型和思考程度不能证明客观或普遍认同。
取字节不等于理解/看图；哈希链/owner/只读模板不认证身份或强制权限。
工具两次同类失败换方法，保留有效改动，只恢复自己造成的破坏；缺能力明确未验证。
事件等待审核，不反复催促；约5分钟无实质进展才检查阻碍。不为10分无限复验。
