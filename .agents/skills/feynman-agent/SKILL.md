# 费曼 Agent · Feynman Agent

用户命名的跨项目调用入口，复用 [完整工作流](../independent-review-workflow/SKILL.md)，不另设审核标准。

1. 承接当前项目已明确的任务和授权范围；没有具体任务时只询问任务内容，不凭空修改项目。
2. 先解析本技能文件的真实路径（用户级安装可能是软链或目录联接），以真实文件所在目录定位完整工作流及其引用。仓库根目录是该目录的 `../../..`；确认存在 `bin/workflow.mjs` 和 `docs/review-policy.md`。缺失时报错，不把单独复制的技能当成完整安装。
3. 读取完整工作流和按需协议，简短告知已启用费曼 Agent，然后按策略组织实现、自检与必要审核。目标项目规则和最新用户要求优先；工作流仓库不等于目标项目。

## 角色与运行边界

- 主会话负责统筹，预期 GPT-6.1 Sol / high；执行子 Agent 使用 GPT-6 Sol / low；独立审核子 Agent 使用 GPT-6.1 Sol / high。Gemini 默认关闭。
- Skill 不切换主会话模型，仓库配置不自动作用于其他项目。委派时显式指定模型与思考程度；环境不支持或运行身份不可见时如实说明，不把配置当成实际生效的证据。
- 执行者与首次盲审均使用独立上下文，首次盲审 fork_turns=none。只传当前任务的中性要求、合同、冻结源码及原始证据；不传执行自评、设计辩护、私有推理、旧通过结论或用户历史记忆。普通返工复用各自连续上下文，遵循完整工作流的哈希取证和失效规则。
- 调用授权任务所需的子 Agent 分工，不额外授权发布、发消息或创建侧栏聊天。模型、权限和外部操作仍受宿主能力与用户授权约束。
- CLI 使用解析后的工作流绝对路径，并显式传入目标项目根目录。审核产物按目标任务隔离；不要为调用修改目标项目 AGENTS.md 或全局默认模型。

用户级安装和跨设备边界见 [安装说明](../../../docs/install.md)。
