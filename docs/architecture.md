# 项目结构与调用关系

## 原生核心

bin/workflow.mjs统一处理参数、文件输入与JSON输出，src/review只导出可复用函数，不启动进程/模型。

| 模块 | 职责 |
| --- | --- |
| src/review/gate.mjs | 校验启动评估，计算动作、理由、输入绑定哈希 |
| src/review/contract.mjs | 原子合同、冻结与哈希、schema3报告、旧问题复验、分离状态 |
| src/review/context.mjs | 审核者取证登记、字节读取、连续上下文复用计划 |
| src/review/dimensions.mjs | 可选诊断维度的数据定义；无旧评分规则 |
| scripts/manifest.mjs | 发布文件范围与大小/哈希完整性 |
| scripts/validate.mjs | 离线源码、引用、测试和清单验证 |

示例：import { decideReview } from './src/review/gate.mjs'。作为仓库内Node包调用时也可使用package.json导出的contract/context/gate子路径。本包private=true，不发布npm包；跨项目用完整本地路径，不默认安装全局工具。

核心不导入adapters/gemini。可选适配器可以引用共享诊断维度，但其schema2、旧全10状态不能控制schema3验收。

## 角色与数据流

执行者GPT-6 Sol/low负责生产写入，统筹审核者GPT-6.1 Sol/high负责中性合同/启动和审核。统筹态与盲审态隔离为不同上下文；角色数量不是实际进程数量限制，也不需要额外常驻裁判。

允许的数据流：原始要求/规则/合同→执行者；冻结原始文件/证据→盲审；有证据的问题事实/目标/保留条件→执行者修复。禁止执行自评/辩护/推荐结论→首次盲审，以及统筹私有推理/预期评分→执行者。

宿主Agent负责委派和真实权限；离线工具不调模型、不传消息、不发布。代理配置只是模板，无法强制实际权限。共享文件系统中审计所有权属于流程约束；强隔离需独立受控环境。

## 可维护性

技能只保留角色、流程与路由；字段和启动定义只在对应协议维护。README提供入口，CLI提供参数，测试验证行为而非文案。新增命令必须同时有可调用入口、必要边界测试与文档；改目录后运行引用/清单校验。

runtime是本机产物，不是分发内容。旧报告和实现说明不放入首次阅读区；阅读索引与源码/证据一并冻结。发布清单采用显式顶层目录/文件白名单和文本类型约束，再人工核对暂存差异。
