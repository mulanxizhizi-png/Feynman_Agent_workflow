# 操作顺序

1. 主对话读取用户要求与目标项目规则，确定允许修改的范围、事实来源与固定验收标准。
2. 委派Sol实现，记录实际模型；保留业务、原图与无关用户改动。
3. 冻结版本，完成语法/资源检查，在获准页面获取真实截图和技术证据。
4. 独立Astra只读审核代码与证据，Gemini官方API评分相同版本的真实截图。
5. 主对话裁决冲突，以用户要求/事实/规则为先。仅采纳有证据、可执行的反馈。
6. Sol修复后生成新截图，向Gemini传上一轮报告，逐项复验原问题ID；一般最多三轮。
7. 记录真实结果、未通过与未验证项。全七维10不替代字体、交互、资源与代码验收。

使用一个主对话管理子Agent。Gemini属于外部API调用，不是另一个需要用户同步的主对话。
子Agent配置与API脚本不自动组成无人值守调度器；需要主对话在应用中保持工作。
